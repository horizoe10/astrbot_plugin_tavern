# v0.12.0 数据库迁移说明

## 目标版本

v0.12.0 使用 SQLite Schema 12。启动时读取 `tavern_meta.schema_version`，对旧库创建迁移备份后逐级执行已有迁移，禁止跨版本猜测结构。

## Schema 12

新增 `notification_outbox`，保存：通知 ID、会话 ID、平台与平台实例、群/私聊目标、文本、种类、去重键、状态、尝试次数、最后错误、时间戳。去重键防止重启或重复事件造成同一通知多次排队。

## 迁移行为

- 新库直接创建当前结构与内置世界。
- 旧库保留原文件路径和稳定业务 ID。
- 升级备份路径记录在迁移状态中；失败时事务回滚并保留备份。
- 旧计时器的缺失字段由运行时兼容迁移补齐，不修改已完成/已取消计时器的业务结论。
- 导出包标注 Schema 12；旧插件不能安全导入后继续写入。

## 数据一致性

通知发件箱与剧情事件分离；忽略通知不会回滚剧情。运行副本继续使用 `instance_configs.world_snapshot_json`。回滚快照恢复回合、选项、投票、计时器和工作流状态，但不会把无关的外部发送结果伪装为未发送。

## 验证 SQL

管理员通常不需要手工执行 SQL。若只读诊断，可确认 `tavern_meta` 的 `schema_version=12`、`notification_outbox` 存在，并在 WebUI 关于页查看相同版本。不要直接修改生产数据库。
